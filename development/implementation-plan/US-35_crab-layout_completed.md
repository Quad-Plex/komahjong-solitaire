# US-35 — Crab layout (12th layout, fills the 3×4 picker)

As a player, I want the "Crab" board shape so the layout picker is fully filled out
as a clean 3×4 grid (12 cards, no empty slot) with one more recognizable shape.

## Why Crab

The picker today (`mahjonglayoutselect.lua`) uses `cols = 3` and
`rows = math.max(3, math.ceil(#ids / cols))`. With the current 11 registered
layouts that is `ceil(11/3) = 4` rows — i.e. a 3×4 grid with **one empty slot**
in the last row. Adding exactly one more layout makes it `ceil(12/3) = 4` rows
with 12 cards: a fully filled 3×4.

All 10 GNOME Mahjongg maps are already implemented (Turtle, Spider, Bridge,
Ziggurat, Cloud, Tic-Tac-Toe, Red Dragon, Overpass, Pyramid's Walls,
Confounding Cross, Taipei — note Spider was an older GNOME map, so GNOME is
exhausted). The new layout is taken from **KDE KMahjongg**'s open layout
collection, which ships ~49 `.layout` files in a parseable text format.

Candidate screening (KMahjongg `layouts/`, counted via a quarter-tile parser):

| layout    | tiles | layers (per-layer)            | grid x / y       | verdict |
|-----------|-------|-------------------------------|------------------|---------|
| cat       | 144   | L0=87 L1=40 L2=14 L3=3        | x0..17 y0..7     | too wide (18) vs our widest (Red Dragon x0..14) |
| dragon    | 144   | L0=62 L1=49 L2=19 L3=14       | x0..14 y0..7     | name/shape collides with our "Red Dragon" |
| **crab**  | **144** | **L0=77 L1=50 L2=15 L3=2**  | **x1..14 y0..7** | **chosen** — classic MS Mahjong Titans shape, fits our footprint |
| castle    | 156   | —                             | —                | not 144 (deck mismatch) |
| pyramid   | 204   | —                             | —                | not 144 |
| girl      | 178   | —                             | —                | not 144 |
| penta     | 130   | —                             | —                | not 144 |
| 4_winds   | 128   | —                             | —                | not 144 |
| arena / balance / eagle / enterprise / arrow / garden | 144 | single layer (flat L0=144) | very tall (y up to 30+) | flat 1-layer shapes; trivial and won't thumbnail/fit |

**Decision: Crab** — 144 tiles (matches our standard deck), 4 layers
(77/50/15/2), grid extents `x=1..14, y=0..7` (same footprint as Red Dragon),
uses the half-grid in places (x.5 / y.5) which our layout-agnostic bevel &
free-tile logic already handles unchanged (see AGENTS.md contract 3 / Red
Dragon). It's the iconic Microsoft *Mahjong Titans* "Crab" and is visually
distinct from all 11 existing shapes.

## Source / provenance

- Upstream file: KDE KMahjongg `layouts/crab.layout`
  (https://invent.kde.org/games/kmahjongg — fetch via the repository files API,
  path `layouts/crab.layout`, ref `master`). License: GPL-2.0-or-later.
- KMahjongg layout format: a header (`kmahjongg-layout-v1.1`, then `w32`/`h16`/
  `d4`) followed by `# Level N` sections; each section is a grid of `w`×`h`
  *quarter-tile* cells. The characters `1 2 / 4 3` form one tile's 2×2 quarter
  block; a `1` marks a tile's top-left quarter, so one tile = exactly one `1`.
  Tile coordinates in our units = `(qx/2, qy/2)` (can be `.5`).
- We transcribe the **coordinate facts** (tile positions) into our `spec` table
  format. Nothing else from the upstream file is copied.

### 2. The `CRAB_SPEC` data (per-layer positions)

(`kind = "tile"`). This is a valid spec as-is (`buildLayout` flattens any mix of
`block`/`row`/`column`/`tile`/`set` to positions, and `checkShape`'s
`for x = s.x_min, s.x_max` works with float half-grid bounds — see Red Dragon).

For style consistency with the other specs (which prefer `block` for filled
rectangles), contiguous 2D runs MAY be compacted into `block` entries
(e.g. Layer 0's two `x=1.5..4.5, y=0..1` rows are the 8-tile half-grid block
`{ kind="block", x_min=1.5, x_max=4.5, y_min=0, y_max=1 }`). Compaction is
optional and cosmetic; the counts/positions below are the source of truth.

### 5. Update existing harnesses that hardcode the 11-layout registry

11 harnesses assert `#ids == 11` plus the full sorted id order. Adding `crab`
bumps the count to 12 and inserts `crab` at sorted index 4 (shifting
`overpass..ziggurat` from slots 4..11 to slots 5..12). Files + the offending
line:

- `tests/us14_layouts.lua` — lines 62-66 (registry enum) **and** the
  `deregisterLayout`-restores-order block at lines 385-391 (which re-asserts
  the full 11-id order after removing a `toy`). Both become `== 12` with
  `ids[4] == "crab"` and slots 5..12 = the old 4..11.

- `tests/us16_bridge.lua` — lines 50-55.
- `tests/us22_ziggurat.lua` — its `#ids == 11` block.
- `tests/us23_cloud.lua`, `tests/us24_tictactoe.lua`,
  `tests/us25_red_dragon.lua`, `tests/us26_overpass.lua`,
  `tests/us27_pyramid.lua`, `tests/us28_confounding.lua`,
  `tests/us29_taipei.lua` — each has one `#ids == 11` + ordered-id assertion
